# WebConsole implementation

The package API and HTTP routes are defined by `console.go` (construction,
configuration, embedded assets and request dispatch). The implementation is
organized by responsibility; all files remain in the same Go package:

- `models.go`, `operational_models.go`: response types
- `snapshot.go`, `resources.go`, `gateway_health.go`: summary and resource status
- `logs.go`, `events.go`, `config.go`: log queries, event streaming and configuration history
- `dpi.go`, `remote_identity.go`, `address_sets.go`, `services.go`: connection enrichment
- `clients.go`, `fingerprints.go`, `leases.go`, `neighbors.go`: client observations
- `interfaces.go`, `routes.go`, `vpn.go`, `sam.go`: network status
- `operational.go`: operational HTML views
- `system_usage.go`, `metrics.go`: local usage sampling and instrumentation
- `helpers.go`: shared formatting, parsing and collection helpers

Tests remain package-level so moving code does not change its visibility.
`routing_test.go` checks the read-only HTTP routing contract, including base-path
handling and error routes. Run `go test ./pkg/webconsole` and
`go test -race ./pkg/webconsole` from the repository root. The fixture-backed
browser workflow is `make webconsole-screenshot`; it does not require a router.

The embedded `static/` directory is generated by `make webconsole-build` from
`webconsole/`. A Go-only reorganization must not change these assets.

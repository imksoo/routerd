WireGuardPeer

各资源的配置 · Kind/name · when · dependsOn

apiVersion: net.routerd.net/v1alpha1 · metadata.name

定义已声明 WireGuardInterface 上的对等端。AllowedIPs 配置 WireGuard 的加密路由；此控制器不会自动创建普通 IP 路由。

指定条件与引用关系

  • 对等端是接口完整 wg setconf 配置的一部分，并非独立服务。同 metadata.name 的明确对等端会覆盖 peersFrom 生成的对等端，即使 interface 不同。
  • presharedKey 优先于 presharedKeyFile，两者不互斥。只有未直接指定时才读文件并移除首尾空白；缺少、无法读取或空文件会使实际应用失败。
  • Connected 表示观察到握手时间戳，经过时间另行报告；不保证握手是最近发生或目标可达。有 endpoint 但无握手时为 Waiting/NoHandshakeYet。

配置语法

这是说明用语法，不是可直接复制的YAML。未加括号的字段在父条目内必填；[ ... ]表示按条件可省略，<类型>为替换值，(a | b)表示选项。选填父条目内仍可能有必填子条目。条件必填、互斥与实际默认值请见下表；常规YAML请使用链接示例。

- apiVersion: net.routerd.net/v1alpha1
  kind: WireGuardPeer
  metadata:
    name: "<name>"
  spec:
    allowedIPs:
      - <string>
    [ endpoint: <string> ]
    interface: <string>
    [ persistentKeepalive: <integer> ]
    [ presharedKey: <string> ]
    [ presharedKeyFile: <string> ]
    publicKey: <string>

字段含义与默认值

选填父条目的必填子条目仅在使用父条目时需要。其他具体条件列于说明；[ ... ]选项仍可能需要择一。

YAML 指定要求 类型与限制 字段含义与默认值
spec.interface 必填 string 必填，同一 Router 中已有 WireGuardInterface 的 metadata.name，仅填 OS ifname 不足以建立引用。
spec.publicKey 必填 string 必填的对等端 WireGuard Base64 公钥。验证仅检查非空，不解码确认长度；应用时由 wg 检查。
spec.allowedIPs 必填 array 必填且不可为空的 IPv4/IPv6 CIDR 列表，控制发送数据包的对等端选择及接收数据包允许的源地址。不会补入前缀或创建普通路由。
spec.endpoint 选填 string 可选的对等端 host:UDP-port，IPv6 使用 [IPv6]:port。空值省略 Endpoint，可从收到的数据包学习端点。routerd 配置验证不检查语法或 DNS 可达性，应用时由 wg 处理。
spec.persistentKeepalive 选填 integer; minimum=0; maximum=65535 持续保活数据包间隔秒数，整数 0–65535；默认 0 表示禁用。不是握手成功期限。
spec.presharedKey 选填 string 可选的额外对称密钥，使用 WireGuard Base64 格式，默认无。与 presharedKeyFile 并用不报互斥错误，优先使用此值。
spec.presharedKeyFile 选填 string 可选的路由器本机文件，内容为预共享密钥本身，不是环境变量文件。缺少时不会生成密钥，仅在 presharedKey 为空时读取。

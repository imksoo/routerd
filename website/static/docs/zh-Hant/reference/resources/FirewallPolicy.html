FirewallPolicy

各資源的設定 · Kind/name · when · dependsOn

apiVersion: firewall.routerd.net/v1alpha1 · metadata.name

設定與區域及明確規則搭配的共用隱含防火牆選項。多個資源會彙總，不是獨立套用。

指定條件與參照關係

  • 沒有必填 spec 欄位。logDeny 在多個資源間取 OR。產生器的 sameRoleAccept 從 true 開始且沒有設為 false 的路徑，因此目前填 false 也無法停用相同角色間轉送。
  • Linux nftables 與 FreeBSD PF 的隱含/明確規則順序不同。PF 在已允許路徑的明確拒絕前產生廣泛隱含允許；Linux 在該區域配對的隱含動作前產生明確規則。不可假定明確拒絕能覆蓋所有隱含、控制或狀態例外。

YAML定義

此處列出所有欄位的結構，不是可直接套用的設定範例。請替換佔位值、省略不使用的選項，並選擇相容的組合。顯示值只表示型別；有效預設值及條件列於下方欄位說明。必填標記來自JSON Schema，表示在所屬物件內必須指定；語意驗證可能要求其他欄位或參照。

- apiVersion: firewall.routerd.net/v1alpha1
  kind: FirewallPolicy
  metadata:
    name: "<name>"
  spec:
    logDeny: true # 選填; boolean
    sameRoleAccept: true # 選填; boolean

欄位意義與預設值

YAML 欄位意義與預設值
spec.logDeny 預設 false，任一資源為 true 即啟用 Linux 隱含 input/forward 拒絕紀錄。明確 drop 仍需其 log 旗標。目前 PF 不讀取此選項。
spec.sameRoleAccept 解碼預設 false，但產生器有效預設固定 true，false 無效。Linux 包含 untrust 對 untrust；PF 不產生其廣泛隱含轉送允許。

實作: pkg/api/specs.go · pkg/config/validate_firewall.go · pkg/render/nftables.go · pkg/render/pf.go

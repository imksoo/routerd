# Linux の WAN DHCPv4 サーバ撤回および復帰

- 実行時のソースリビジョンは `1c1f5cb37b79472d6cf2e508f9b4b5db2552d67c` です。
  親プロセスは `a479104f` の Linux 配布物を使いました。
  DHCPv4 子プロセスは `3a18c5e3` の `routerd-dhcpv4-client` へ置き換えました。
- 構成は隔離した PVE の VLAN 3132 です。
  VM219 は新規の 1.5 設定と候補版を実行しました。
  VM220 は `198.18.46.1/24` の独立した `dnsmasq` DHCP サーバです。
  VM219 の WAN には事前の IPv4 アドレスを設定していません。
- 候補の DHCPv4 子プロセスは PID 3409 でした。
  初期リースは `198.18.46.100/24`、既定経路はメトリック 4242 の `198.18.46.1` です。
  DNS サーバは `198.18.46.1` です。リース時間は 120 秒でした。
- `2026-11-02T06:02:17Z` に VM220 の DHCP サーバを停止しました。
  PID 3409 は継続しました。
  `06:02:55Z` に `Renewing`、`06:03:40Z` に `Rebinding` を記録しました。
  `06:03:55Z` には `Discovering` となりました。
  この時点で WAN の IPv4 アドレスと既定経路は消え、リース記録から DNS サーバも消えました。
- `2026-11-02T06:04:11Z` に VM220 の DHCP サーバを再開しました。
  VM220 のパケット記録は `06:04:23Z` の Discover と、`06:04:26Z` の Offer、Request、ACK を示します。
  VM219 は `06:04:26Z` に `Requesting`、続けて `Bound` を記録しました。
  PID 3409 のまま `198.18.46.100/24`、既定経路、DNS サーバを復帰しました。
- 復帰後のファイアウォールでは、WAN から自装置への UDP 宛先ポート 68 だけが 2 パケット通過しました。
  WAN から LAN への拒否規則のカウンターは 0 パケットでした。
- この記録は、DHCPv4 の独立サーバ撤回、再バインド、有効期限切れ、復帰を対象にします。
  サーバ識別子変更、NAK、複数 WAN、転送通信、FreeBSD は未認定です。
- 試験開始時には `/run` が実行禁止であること、ISO 内の設定が読み取り専用であることを確認しました。
  候補を `/tmp` へ展開し、設定を複製してから実行しました。
  最初に旧子プロセスが選ばれた起動は、`PATH` を訂正したため証跡から除外しました。

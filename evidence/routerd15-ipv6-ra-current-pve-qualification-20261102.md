# routerd 1.5 IPv6 RA 分離 PVE 実通信検証（2026-11-02）

## 結論

`58b66728` の Linux 配布物を実行するPVE VM219から、独立VM220のLAN側名前空間へIPv6 Router Advertisement（RA）を送信しました。クライアントのSLAACアドレスと既定経路を確認し、資源撤去後には既定経路が消え、SLAACアドレスが非推奨状態へ遷移することを確認しました。

## 試験条件

- routerd 実行VM: PVE VM219
- 独立クライアント: PVE VM220 の `rd15-lan-peer` 名前空間
- 接続ネットワーク: `br-rd15-lab` VLAN 3131
- RA資源: `IPv6RouterAdvertisement/lan-ula-ra`
- 広告プレフィックス: `fd42:18:0:1::/64`
- 有効期間 / 優先期間: 7200秒 / 3600秒
- RDNSS: `fd42:18:0:1::1`
- 検証した配布物 SHA-256: `997af0127a5ced70ae446285c5d541e276861bfa54edd75cb47795495aa26bc6`

## 観測

1. RA資源は `Applied` となり、プレフィックス、RDNSS、DNSSLが状態に記録されました。
2. クライアントは `fd42:18:0:1:be24:11ff:fefe:47d0/64` をSLAACで取得しました。
3. クライアントは、VM219のリンクローカルアドレスを次ホップとするIPv6既定経路をRAから取得しました。
4. RA資源を除いた元の21資源構成へ戻すと、クライアントのIPv6既定経路は消え、SLAACアドレスは優先期間0の非推奨状態へ遷移しました。
5. 復元後のVM219は21資源、`Healthy`、現在エラーなしでした。VM220からDHCP、DNS UDP/TCP、NAT、管理通信も再合格しました。

## 範囲外

この試験は静的ULAのRA送受信と撤去だけです。ルーターへULAのサービスアドレスは付与していないため、`fd42:18:0:1::1` への到達性は評価対象外です。DHCPv6-PD、上流からの実プレフィックス、RAに載せたIPv6 DNSの名前解決、DS-Liteは別受入です。

# routerd 1.0 と 1.5 の冷間切替・切戻し PVE 実施記録（2026-11-02）

## 結論

PVE VM219 と独立クライアント VM220 の隔離 VLAN 3131-3133 で、routerd 1.0 `e3b49dbb` から routerd 1.5 `58b66728` への冷間切替を実施しました。1.5 の再起動後、独立クライアントの DHCP 再取得、DNS の UDP/TCP、NAT、管理通信、VLAN 分離は成功しました。

逆方向の切戻しは未合格です。保存した1.0生設定は、隔離 VM に存在しない `192.168.123.129:8080` を WebConsole の待受先として指定しており、1.0の起動は失敗しました。隔離 VM の実アドレスは `192.168.1.246/24` です。生設定を別環境へそのまま適用して合格にすることはしませんでした。

VM219 は保存済みの1.5回復組を用いて `58b66728`、21資源、`Healthy` へ復元済みです。VM220 の DHCP プロセスと起動識別子は維持され、通信と分離も再確認しました。

## 実施結果

1. 1.5の状態、設定、systemd 受領記録を停止後に退避しました。
2. 1.0を導入し、旧設定の構文検証、サービス起動、21資源の正常状態を確認しました。VM220 の DHCP、DNS、NAT、管理通信、VLAN 分離は合格し、DHCP リース更新も観測しました。
3. 1.5へ切り替える際は、1.0の状態を先に退避しました。インストーラーが作成した1.0移管記録を新しい1.5状態側へ残した結果、静的アドレス・経路の所有権を引き継ぎ、`Healthy` になりました。
4. 1.5を再起動後、VM220 の DHCP アドレスはいったん撤去されました。同じ `udhcpc` プロセスが自動再取得し、その後の DHCP、DNS UDP/TCP、NAT、管理通信、VLAN 分離は合格しました。
5. 1.5で空構成を適用し、資源数0の `Healthy` を確認してから1.0回復組を復元しました。
6. 1.0生設定の WebConsole が隔離 VM に存在しない `192.168.123.129:8080` へ待ち受けようとして失敗しました。このため逆方向の切戻しは未合格です。
7. 回復処理では systemd の自動再始動と状態展開が競合し、展開先 SQLite が破損しました。サービスを実行時に停止固定し、退避アーカイブを別場所で `PRAGMA integrity_check = ok` と確認してから復元しました。
8. 復元後の VM219 は `58b66728`、21資源、`Healthy` です。VM220 は同じ起動識別子と同じ `udhcpc` プロセスを保ち、通信と分離が合格しました。

## 未合格を解消する条件

切戻しを合格にするには、隔離環境の実アドレスと管理保護要件に対応した1.0側の変換構成を作成し、WebConsole、管理接続制限、DHCP、DNS、NAT、VLAN 分離を1.0で確認してから、同じ回復組へ戻す必要があります。実機の管理アドレスを隔離 VM へ手作業で追加して合格にすることはしません。

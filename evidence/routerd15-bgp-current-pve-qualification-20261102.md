# routerd 1.5 BGP 分離 PVE 実通信検証（2026-11-02）

## 結論

`58b66728` の Linux 配布物を実行する PVE VM219 と、独立VM220のWAN側名前空間で、BGPの確立、経路交換、ピア停止時の経路撤回、ピア再起動後の復帰を確認しました。終了後はBGP資源を撤去し、元のDHCP、DNS、NAT、管理通信、VLAN分離を再確認しました。

## 対象

| 項目 | 値 |
| --- | --- |
| routerd リビジョン | `58b66728` |
| 配布物 SHA-256 | `997af0127a5ced70ae446285c5d541e276861bfa54edd75cb47795495aa26bc6` |
| routerd 実行VM | PVE VM219 |
| 独立ピア | PVE VM220 の `rd15-wan-peer` 名前空間 |
| 接続ネットワーク | `br-rd15-lab` VLAN 3132 |
| routerd ASN / ID | 64500 / `198.18.16.2` |
| ピア ASN / ID | 64501 / `198.18.16.1` |
| 受信許可経路 | `10.77.60.0/24` |
| 送信許可経路 | `198.18.15.0/24` |

VM220ではFRRouting `bgpd` を名前空間内で一時起動しました。実回線、旧構成のピア、外部ネットワークには接続していません。

## 観測

1. 既存の21資源構成へ `BGPRouter/isolated-edge` と `BGPPeer/isolated-peer` だけを一時追加し、構文検証と適用が成功しました。
2. `BGPPeer/isolated-peer` は `SESSION_STATE_ESTABLISHED`、`establishedPeers: 1`、受信プレフィックス数1となりました。
3. VM219のカーネル経路表に `10.77.60.0/24 via 198.18.16.1 dev rd15-wan proto bgp metric 200` を確認しました。
4. ピア側では `198.18.15.0/24` をAS 64500から1経路として受信しました。
5. ピアの `bgpd` 停止後、VM219は `Reconverging`、確立ピア数0となり、`10.77.60.0/24` の経路は消えました。
6. 同一設定でピアを再起動後、Established、受信プレフィックス数1、カーネル経路が復帰しました。
7. 元の21資源構成を適用して `routerd-bgp` の停止と経路撤去を確認しました。続けてVM220の実通信試験でDHCP、DNS UDP/TCP、NAT、管理通信、WAN/LAN/管理/DNS分離が合格しました。

## 範囲外

これはBGPの最小相互接続試験です。旧設定に含まれる実運用ピア、経路集合、認証情報、障害時の全経路収束は、実運用の値を使わない別の受入対象です。

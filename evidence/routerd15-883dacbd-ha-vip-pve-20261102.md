# Linux HA 仮想アドレスの実通信試験

## 結果

`883dacbd` の Linux 候補パッケージで、VRRP 仮想アドレスの通信、二候補間の引継ぎ、停止した候補の再起動、構成撤回と復旧を確認しました。

## 実行対象

- ソースリビジョン: `883dacbd3df3f0725e07f2985ccfcf559089b3f4`
- パッケージ SHA-256: `cd763b1a1356053dd6e7400358119a0edfbf23c674a16a4fd07ff580d7de83ad`
- 仮想マシン: VM221 が優先度 150 の候補、VM222 が優先度 100 の候補、VM223 が独立クライアント
- 分離経路: VLAN 3152
- 構成: 既存の LAN IPv4 アドレスは外部管理とし、routerd は `172.18.0.1/32` の VRRP 仮想アドレスだけを所有

## 観測

1. VM221 は主系、VM222 は待機系となり、VM223 から仮想アドレスへの ICMP は成功しました。
2. VM222 が主系の状態で停止すると、VM221 が主系へ移り、VM223 の応答先 MAC アドレスと ICMP 通信も VM221 側へ移りました。
3. VM222 を再起動すると待機系へ戻り、非プリエンプト設定により VM221 の主系所有と VM223 の通信は維持されました。
4. 両候補へ空の新規 1.5 構成を適用すると、仮想アドレスは両方から消え、VM223 の ICMP は到達不能になりました。
5. 読み取り専用 ISO 上の元構成を別名で複製して再適用すると、両候補は `Healthy` となり、VM221 が主系、VM223 の ICMP は再び成功しました。

## 範囲外

DHCP リース継続、既存 TCP 接続の無損失化、経路・NAT・IPv6 の引継ぎ、物理回線障害、長時間障害、FreeBSD は未確認です。
この結果は HA 機能全体、Linux 全体、または置換可能品質の合格を意味しません。

## 復元

VM221、VM222、VM223 を試験前のスナップショットへ戻しました。
三台は稼働状態へ復元し、VM221 と VM222 の既存 `routerd` サービスは `active` です。
試験用 ISO、一時配置、三つの試験用スナップショットは削除済みです。

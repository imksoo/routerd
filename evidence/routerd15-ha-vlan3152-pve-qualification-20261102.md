# routerd 1.5 VRRP と DHCP の分離 PVE 実機検証（2026-11-02）

## 結論

PVE 上で、routerd 1.5 の同一リビジョン `cc952492` を実行する2台のルーターと、独立クライアントを未使用 VLAN 3152 へ分離しました。優先系の強制停止、待機系への仮想アドレス引継ぎ、DHCP の再取得、優先系復旧後の非プリエンプトを確認しました。

これは VRRP と DHCPv4 の実通信検証です。routerd 1.0 の全機能同等性、インターネット側転送、IPv6、BGP、ファイアウォール、および FreeBSD は、この試験だけでは確認していません。

## 分離の確認

最初に VLAN 302 を使った試行では、既存 VM208/209 が同じ VLAN に接続していることを後から検出しました。停止済みの VM221 と同じ `172.18.0.2` が DHCP 応答元として観測されたため、その試行の連続疎通・DHCP結果は本証跡から除外しました。

VLAN 3152 は PVE の仮想マシン設定を検索して未使用であることを確認後、VM221 の `net1`、VM222 の `net1`、VM223 の `net0` にだけ割り当てました。以降の結果は VLAN 3152 のものだけです。

## 観測結果

1. VM221 は `VirtualAddress/lan-vip` の `role: master` として `172.18.0.1/32` を保持しました。VM222 は `role: backup` でした。
2. VM223 は BusyBox `udhcpc` で `172.18.1.142` を取得しました。DHCP サーバーは `172.18.0.2`、既定経路は `172.18.0.1` でした。VM221 の lease ファイルにも同じ MAC アドレスとアドレスを記録しました。
3. VM223 から仮想アドレスへの ICMP は、停止前に3/3応答しました。
4. `qm stop 221 --timeout 0` で優先系を強制停止しました。停止開始は `17:25:09.922Z`、VM222 のマスター遷移は `17:25:15.787569730Z` でした。
5. クライアントの約200ミリ秒間隔のICMP観測では、`17:25:09.775Z`、`17:25:10.978Z`、`17:25:12.181Z` の3標本が1秒タイムアウトでした。最初の再応答は `17:25:13.384Z` でした。停止開始から最初の再応答までは約3.46秒です。この数値は今回の条件での観測であり、サービス水準目標ではありません。
6. VM222 は `role: master` として仮想アドレスを取得し、UDP 67番ポートを待ち受けました。VM223 は DHCP を再取得し、応答元が `172.18.0.3`、既定経路が `172.18.0.1` であることを確認しました。仮想アドレスへのICMPは3/3応答しました。
7. VM221 を再起動後、VM221 は `role: backup`、VM222 は `role: master` のままでした。待受はVM222だけに残りました。VM223 の再DHCPも `172.18.0.3` から成功し、仮想アドレスへのICMPは3/3応答しました。

## 次の検証

この構成を残したまま、WAN VLAN と管理 VLAN を含むルーティング、NAT、DNS、障害時の戻し、旧設定の機能対照を同じ分離原則で検証します。FreeBSD は Linux の未完了機能を閉じてから実施します。

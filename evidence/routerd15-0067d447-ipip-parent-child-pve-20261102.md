# routerd 1.5 現行 Linux PVE IPIP 親子資源の撤回・復旧検証

実行リビジョンは `0067d447` です。
独立した PVE VLAN の相手側と IPIP 実通信を行い、構成撤回と再適用後の復旧を確認しました。

- 実行物: `routerd v20261027.1620 (0067d447)`
- 配布アーカイブ SHA-256: `8e8814884d49f5a23c96b1f3b65e17b03ce57bdacb37b0d58d40daac21470169`
- 候補機: 隔離 PVE VM219
- 独立ピア: 隔離 PVE VM220
- 外側ネットワーク: VLAN 3132、候補機 `198.18.17.2`、独立ピア `198.18.17.1`
- 内側ネットワーク: 候補機 `192.0.2.1/32`、独立ピア `192.0.2.2/32`

## 構成と境界

- `TunnelInterface/ipip-rd15` は IPIP 親を所有し、`IPv4StaticAddress` と `IPv4Route` が子アドレスと経路を適用しました。
- 新規 1.5 設定では `FirewallZone/ipip` が `TunnelInterface/ipip-rd15` を明示参照しました。
- `FirewallZone/wan` は外側 VLAN の IPIP 受信だけを許可しました。独立ピアは内側 ICMP エコー要求だけを受ける一時規則を持ちました。

## 観測結果

- `routerd validate` は通常構成と撤回構成の両方で成功しました。
- 通常構成では `ipip-rd15` に `192.0.2.1/32`、`192.0.2.2/32 dev ipip-rd15` の経路、`if_ipip = "ipip-rd15"`、および `iifname @if_ipip jump ipip_to_self` が生成されました。
- 候補機から独立ピアへの ICMP は 3/3 応答しました。独立ピアから候補機への ICMP も 3/3 応答しました。
- 撤回構成への置換で `ipip-rd15` と `192.0.2.2/32` の経路が消え、独立ピアから候補機への ICMP は 0/2 応答でした。
- 通常構成の再適用後、親、子アドレス、経路、入力ゾーン規則が戻りました。候補機から独立ピア、独立ピアから候補機の ICMP はそれぞれ 3/3 応答しました。

## 復元確認

- VM219、VM220、VM224 は試験前のスナップショットへ戻しました。試験用の光学媒体接続、スナップショット、PVE 上の ISO と配布アーカイブを削除しました。
- FOU/GUE、複数トンネルの経路制御、高可用性、FreeBSD、物理回線は未検証です。

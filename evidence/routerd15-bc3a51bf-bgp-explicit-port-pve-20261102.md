# routerd 1.5 BGP 明示ポート分離 PVE 実通信検証（2026-11-02）

## 結論

`bc3a51bf` の候補を PVE VM219 で実行し、独立した VM220 の FRRouting `bgpd` と VLAN 3132 で BGP を確立しました。設定値 `198.18.16.1:179` と実行中の接続先アドレスを同一のピアとして扱い、通信状態と `BGPPeer` の状態表示はともに Established でした。

許可経路は Linux カーネル経路表へ導入され、拒否経路は導入されませんでした。独立ピアからの経路撤回と再広報で、候補の経路撤回と復旧も確認しました。

## 対象と観測

| 項目 | 値 |
| --- | --- |
| ソースリビジョン | `bc3a51bfa4450e87ab3d8229ef8281e600f04b64` |
| 候補 `routerd` SHA-256 | `6a5d1eb7c0149c97d30d6e8def8bb927551409461a5f00adcb0ca17ab887e500` |
| 構成 | VM219 候補、VM220 独立 FRRouting、VLAN 3132 |
| 設定ピア | `198.18.16.1:179`、ASN 64501 |
| 受信方針 | 許可 `10.77.60.0/24`、拒否 `10.77.61.0/24` |

1. VM220 は候補から `198.18.15.0/24` を受信しました。
2. VM219 は `10.77.60.0/24 via 198.18.16.1 dev rd15-wan proto bgp metric 200` を導入しました。
3. `10.77.61.0/24` は導入されませんでした。
4. `BGPPeer/upstream` は `established: true`、`SESSION_STATE_ESTABLISHED`、`phase: Established` を報告しました。
5. `routerd-bgp` の再起動回数は 0 でした。
6. VM220 で許可経路を撤回すると VM219 の経路は消え、再広報すると復帰しました。拒否経路は一貫してありませんでした。

## 復元と範囲

試験前の両 VM ディスクスナップショットへ、停止状態で復元しました。VM219 の既存バイナリ SHA-256 と `routerd`・`routerd-dnsmasq` の稼働、VM220 の試験用 VLAN 子インターフェースと FRRouting プロセスの不在を確認し、一時 ISO、作業領域、スナップショットを削除しました。

この証跡は単一 IPv4 eBGP ピアの明示ポート、受信方針、経路撤回・復旧に限ります。IPv6 BGP、ECMP、動的ピア、実運用ピア、FreeBSD は未認定です。

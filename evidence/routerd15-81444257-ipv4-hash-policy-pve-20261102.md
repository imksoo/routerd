# IPv4 ハッシュ方針の三VM PVE実通信・撤回・復旧

対象リビジョンは `81444257bd89a9f3f25ed9fd7e7f1023c6fa18c9` です。候補配布物の SHA-256 は
`a07047cfc3bc3fc9131fc2bbda7e052bc736f0e52cc1deb7229fafa5cdb039a7` でした。

VM219 を候補、VLAN 3131 の VM224 を独立クライアント、VLAN 3132 と VLAN 3133 の VM220 を
独立上流にしました。候補は二つのハッシュ対象を持ちます。経路表 121 はマーク `0x120` と
VLAN 3132、経路表 122 はマーク `0x121` と VLAN 3133 を使用します。

1. 構成の検証と適用は `Healthy` でした。候補は二つの方針規則、二つの既定経路、NAT44、
   および送信元・宛先を入力にするハッシュ規則を導入しました。
2. VM224は異なるIPv4宛先への新規HTTPを完了しました。候補の接続追跡には `mark=288` と
   `mark=289` がありました。VM220は変換送信元 `198.18.16.2` と `198.18.17.1` の両方を記録しました。
3. 空の新規1.5構成への置換で、二つの方針規則、経路表121/122の既定経路、`routerd_policy` 表は
   消えました。VM224の新規HTTPはタイムアウトしました。
4. 検証済み構成を再適用すると、二つの規則、経路、ハッシュ規則が復旧しました。VM224の新規HTTPは
   再び応答しました。

試験後はVM219、VM220、VM224を試験前の状態へ戻しました。試験用ISO、一時配置、スナップショットを
削除し、VM219・VM220は稼働、VM224は停止へ復元しました。

この記録は二経路の静的IPv4ハッシュ方針を対象にします。動的ゲートウェイまたは送信元、VRRP、
物理WAN障害、FreeBSD、および routerd 1.0 全機能の合格判定は対象外です。

# DHCPv6-PD、ルーター広告、IPv6 復旧の現行版 PVE 実行記録

対象リビジョンは \`2bb2a6e3ab4a735c2984a77be586d0010a9bf77b\` です。PVE の隔離 VM219 上で、現行の \`routerd\`、\`routerctl\`、\`routerd-dhcpv6-client\`、\`routerd-dns-resolver\` を起動しました。独立した Kea DHCPv6 サーバー、HTTP 上流、DNS 上流、LAN クライアントは、この VM 内の個別ネットワーク名前空間で動作させました。

この実行は現行バイナリを対象にした隔離 VM の実通信です。VM220・VM224 と VLAN 3131・3132 を使った三 VM 構成の再実行ではありません。三 VM 構成の記録は過去のリビジョンの証跡として別に残し、本記録で置き換えません。

## 実行対象

- 実行 VM: PVE VM219。
- 候補バイナリ: \`routerd\` の SHA-256 は \`6a5d1eb7c0149c97d30d6e8def8bb927551409461a5f00adcb0ca17ab887e500\`。
- 構成: \`tests/fixtures/linux-pd-ra-lifecycle.json\`。
- 実行手順: \`scripts/linux-pd-ra-lifecycle-smoke.sh --disposable-vm\`。
- 独立上流: Kea DHCPv6 が \`2001:db8:1500::/60\` を委任し、後にプロセス再起動なしで \`2001:db8:1501::/60\` へ変更。
- 独立クライアント: LAN 名前空間のカーネル SLAAC クライアント。
- 独立サービス: \`2001:db8:17::1\` の HTTP と DNS。

## 観測結果

1. 初回の委任で、候補は \`2001:db8:1500::/64\` を LAN へ構成して広告しました。クライアントは SLAAC アドレス、ルーター広告由来の既定経路、DNS を取得しました。
2. クライアントから独立 DNS の UDP/TCP 問合せと独立 HTTP 上流への通信が成功しました。HTTP 上流は委任済み \`2001:db8:1500::/64\` の送信元を観測しました。
3. Kea の委任を \`2001:db8:1501::/60\` へ変更すると、候補の LAN アドレス、広告、クライアントの SLAAC アドレス、DNS、HTTP の送信元が新しいプレフィックスへ移行しました。古いルーターアドレスは撤回されました。
4. \`routerd\` 再起動後も、DHCPv6-PD は再度 \`Bound\` となり、SLAAC、DNS、HTTP 転送が復旧しました。
5. Kea を停止して委任の有効期限を満了させると、候補の LAN アドレス、クライアントの既定経路、HTTP 通信が消えました。失効後に古い転送権限が残りませんでした。
6. Kea を再開すると、\`2001:db8:1501::/60\` の委任、SLAAC、DNS、HTTP 転送が自動復旧しました。
7. 再度の上流停止と失効の後、空の 1.5 設定を \`routerctl apply --replace\` で適用しました。資源数 0、Healthy、資源位相の問題なし、制御器エラーなしを確認しました。

実行ログは、初回配布、再採番、失効時の撤回、上流復旧、空設定への撤回、および総合成功をそれぞれ \`PASS\` として出力しました。

## 復元

VM219 は試験前スナップショット \`rd15-current-pd-pre\` へ戻しました。基準 ISO を再接続し、基準バイナリのハッシュと \`routerd\`、\`routerd-dnsmasq\` の稼働を確認した後、スナップショットと試験用 ISO を削除しました。

## 範囲外

- この実行は PVE VM 内の独立ネットワーク名前空間であり、VM220・VM224 を使う VLAN 分離の再実行ではありません。
- WAN 側ルーター広告、物理回線、FreeBSD、IPv6 BGP、ECMP は対象外です。
- この記録は DHCPv6-PD、LAN ルーター広告、IPv6 転送、DNS、失効・復旧・撤回の範囲だけを示します。Linux 全機能または全製品の合格を示すものではありません。

# Linux PPPoE 切断・復旧の実通信試験

## 結果

`883dacbd` の Linux 候補パッケージで、独立した PPPoE アクセスコンセントレータとの PAP/IPCP 接続、切断、復旧を確認しました。
独立 VLAN 上のクライアント通信は、候補ルーターの NAT44 を通り、切断時に停止して復旧後に再開しました。

## 実行対象

- ソースリビジョン: `883dacbd3df3f0725e07f2985ccfcf559089b3f4`
- パッケージ: `dist/linux-amd64/routerd-linux-amd64.tar.gz`
- パッケージ SHA-256: `cd763b1a1356053dd6e7400358119a0edfbf23c674a16a4fd07ff580d7de83ad`
- ビルド: `CGO_ENABLED=0 make dist`
- 仮想マシン: VM219 が候補ルーター、VM220 が rp-pppoe アクセスコンセントレータと HTTP 応答器、VM224 が独立クライアント
- 分離経路: VLAN 3132 を PPPoE 側、VLAN 3131 を LAN 側として使用
- 構成: 新規 routerd 1.5 構成。PAP 認証、`ppp-lab`、既定経路、`198.18.15.0/24` から PPPoE への NAT44 を宣言

## 観測

1. VM219 は `ppp-lab` 上で `100.64.0.10` を取得し、相手 `100.64.0.1` への PPPoE 既定経路を設定しました。状態は `Connected`、正常でした。
2. VM219 の NAT44 規則は `198.18.15.0/24` の送信元を `ppp-lab` で変換しました。
3. VM224 から `100.64.0.1` への ICMP は 3/3 成功しました。VM220 の HTTP 応答は送信元 `100.64.0.10` を記録しました。
4. VM220 の PPPoE アクセスコンセントレータと対応する PPP プロセスを停止しました。VM219 は `Failed` と `Connection terminated.` を公開し、`ppp-lab` は消え、既定経路は `rd15-wan` に戻りました。VM224 の HTTP は接続時間切れでした。
5. 同じアクセスコンセントレータを再起動すると、VM219 は PAP/IPCP を再実行して `100.64.0.10` を回復しました。VM224 の ICMP は再び 3/3 成功し、HTTP 応答も `100.64.0.10` を記録しました。

## 防火壁境界

宣言した NAT44 規則以外の変換規則は追加しませんでした。
切断中は `ppp-lab` が存在せず、VM224 から VM220 の HTTP 応答器へ到達できませんでした。
試験構成は三つの仮想マシンと VLAN 3131/3132 に限定しました。

## 範囲外

IPv6 PPP、CHAP、認証失敗、資格情報の更新、MTU 境界、複数同時セッション、長時間の障害、別実装のアクセスコンセントレータ、物理回線は未確認です。
この結果は PPPoE 全体、Linux 全体、routerd 1.0 の全機能、または置換可能品質の合格を意味しません。

## 復元

VM219、VM220、VM224 を試験前のスナップショットへ戻しました。
VM219 と VM220 の既存 `routerd` サービスは `active`、VM224 は停止状態です。
試験用 ISO、一時配置、三つの試験用スナップショットは削除済みです。

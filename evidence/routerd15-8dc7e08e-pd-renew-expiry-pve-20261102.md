# DHCPv6-PD 更新・期限切れ・復旧実通信試験

- 実行リビジョン: `8dc7e08ec3f286ace9cc1e30cf408971e0506735`
- Linux 配布物 SHA-256: `d945433abfbb86485e3c0e7a42672d3858ecd8b8458ba24ee1b976de0f531023`
- 対象: VM219 の routerd 1.5 候補、VM220 の独立 Kea DHCPv6・IPv6 HTTP ピア、VM224 の独立 SLAAC クライアント
- 分離経路: VLAN 3131 が LAN、VLAN 3132 が WAN、VLAN 3133 が管理
- 構成: `examples/routerd15-pve-home-router-composite.json`

## 観測

1. Kea は更新 10 秒、再バインド 20 秒、有効期限 35 秒の DHCPv6-PD リースを配布しました。これらは期限切れを発生させる試験用のリース値であり、切替時間の目標値ではありません。
2. 候補は `2001:db8:1500::/60` を Bound 状態にし、LAN アドレス `2001:db8:1500::1/64` を設定しました。独立クライアントは SLAAC と既定経路を取得しました。
3. Kea が稼働中、候補は複数の `PrefixRenewed` を記録しました。独立クライアントからの IPv6 HTTP 通信は、委譲済みアドレスを送信元として VM220 に届きました。
4. Kea だけを停止すると、候補は `PrefixExpired` を記録し、LAN の委譲済みアドレスを撤回しました。クライアントの既定経路は消え、IPv6 HTTP 通信は失敗しました。
5. Kea を復帰すると、候補は同じプレフィックスを再び Bound 状態にし、クライアントは既定経路と IPv6 HTTP 通信を自動回復しました。
6. 復旧後、候補の状態は `Healthy` で、全コントローラーの現在エラーはありませんでした。3 台すべての QEMU Guest Agent（QGA）応答も確認しました。

## 範囲

- クライアント側の `dhcpcd` は IPv4 用に起動したため、IPv6 の既定経路受入れを明示して試験しました。これは独立クライアント VM の条件であり、候補機の設定ではありません。
- すべての変更は `rd15-pd-expiry-8dc7e08e-pre` スナップショットへ復元後、試験用 ISO とスナップショットを削除しました。復元後は VM219 と VM220 が起動、VM224 が停止、VM219 の追加 ISO は未接続です。
- この証跡は Linux の DHCPv6-PD 一経路の更新・期限切れ・復旧に限ります。複数プレフィックスの番号変更、稼働中の候補プロセス再起動、PPPoE、冗長化、FreeBSD、および routerd 1.0 全機能の置換可否は未確認です。

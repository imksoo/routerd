# IPv4 マーク方針の三VM PVE実通信・撤回・復旧

対象リビジョンは `81444257bd89a9f3f25ed9fd7e7f1023c6fa18c9` です。候補配布物の SHA-256 は
`a07047cfc3bc3fc9131fc2bbda7e052bc736f0e52cc1deb7229fafa5cdb039a7` でした。

VM219 を候補、VLAN 3131 の VM224 を独立クライアント、VLAN 3132 の VM220 を独立上流にしました。
VM224 は `198.18.15.2`、候補は LAN `198.18.15.1` と WAN `198.18.16.1`、VM220 は
`198.18.16.2` と HTTP 宛先 `192.0.2.1:18082` を使用しました。

新規 1.5 構成の `EgressRoutePolicy` は、LAN送信元にマーク `0x120`、優先度 10121、経路表 121 の
既定経路を定義しました。NAT44、LAN信頼ゾーン、WAN非信頼ゾーンを同時に定義しました。

1. 構成の検証と適用は `Healthy` でした。候補はマーク規則、優先度 10121 の規則、経路表 121 の
   `198.18.16.2` 経由既定経路を導入しました。
2. VM224 の新規 HTTP は VM220 で応答しました。候補の接続追跡記録にはクライアント接続のマークが
   あり、VM220 は変換後送信元 `198.18.16.1` を記録しました。
3. 空の新規 1.5 構成への置換で、規則、経路表 121 の既定経路、`routerd_policy` 表は消えました。
   VM224 の新規 HTTP はタイムアウトしました。
4. 同じ構成の再適用で規則、既定経路、マーク規則を再導入しました。VM224 の新規 HTTP は復旧し、
   VM220 は同じ変換後送信元を記録しました。

試験後は VM219、VM220、VM224 を試験前のスナップショットへ戻しました。ISO、一時配置、
スナップショットを削除し、VM219・VM220は稼働、VM224は停止へ復元しました。

この記録は単一の静的IPv4マーク方針を対象にします。ハッシュ方式、動的ゲートウェイまたは送信元、
VRRP、物理WAN障害、FreeBSD、および routerd 1.0 全機能の合格判定は対象外です。

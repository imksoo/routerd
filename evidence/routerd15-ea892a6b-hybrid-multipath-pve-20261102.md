# routerd 1.5 現行 Linux PVE 複数トンネル HybridRoute 撤回・復旧検証

実行リビジョンは ea892a6b です。独立 PVE VLAN のクライアントから、FOU と GUE の別トンネルへ展開した二つの HybridRoute を実通信で確認しました。

- 実行物: routerd v20261027.1620 (ea892a6b)
- 候補機: PVE VM219。独立ピア: VM220。独立クライアント: VM224。
- 外側 VLAN 3132: 候補機 198.18.16.2、FOU ピア 198.18.16.1、GUE ピア 198.18.16.3。
- 内側: FOU は 192.0.2.1/32 と 192.0.2.2/32、GUE は 192.0.2.5/32 と 192.0.2.6/32。

## 観測結果

- TunnelInterface/fou-mpath と TunnelInterface/gue-mpath は同時に生成されました。HybridRoute/via-fou は 10.90.1.1/32 を FOU 親へ、HybridRoute/via-gue は 10.90.2.1/32 を GUE 親へ展開しました。
- 独立クライアントから二つの宛先への ICMP はそれぞれ 3/3 成功しました。
- HybridRoute/via-fou だけを撤回すると、10.90.1.1 は候補機から到達不能になりました。10.90.2.1 は GUE 経路で 3/3 を維持しました。
- 再適用後、二つの下位経路が戻り、二つの宛先への ICMP はともに 3/3 へ復旧しました。
- VM219、VM220、VM224 は試験前スナップショットへ戻しました。試験用の光学媒体接続、スナップショット、PVE 上の ISO と配布アーカイブを削除しました。

## 範囲外

- 同一の外側ローカル・リモート組に複数の IPIP 親は作成できません。複数トンネルには異なる外側相手識別子を使いました。
- 高可用性、FreeBSD、物理回線、および全 HybridRoute 機能の合格は示しません。

# Linux の WAN DHCPv4 VLAN 取得および更新

- 対象リビジョンは `3a18c5e35ef5ec2f694c30368448068278857417` です。
- 構成は隔離した PVE の VLAN 3132 です。
  VM219 では、新規の 1.5 設定と候補版を動かしました。
  既存の WAN IPv4 アドレスは設定しませんでした。
  VM220 には、`198.18.46.1/24` の独立した `dnsmasq` DHCP サーバを配置しました。
- 初回通信では、VM220 のパケット取得で DHCP の4段階通信（DORA）を確認しました。
  DHCP Discover は `0.0.0.0:68` から `255.255.255.255:67` へ送信されました。
  続けて Offer、Request、ACK を確認しました。
  VM219 は `198.18.46.100/24` で `Bound` となりました。
  既定経路はメトリック 4242 の `198.18.46.1` です。DNS サーバは `198.18.46.1` です。
- 更新では、DHCP クライアントのプロセス ID が同一のまま残りました。
  イベント列は `05:54:45` と `05:55:40` に `Renewing` から `Bound` へ遷移しました。
  いずれも 120 秒のリース時刻を更新しました。
  子プロセスの終了を監督プロセスが記録した形跡はありません。
- 直接取得できた独立ピアのパケットは、初回の DORA です。
  更新 ACK のパケット記録は保存できませんでした。
  更新は、独立サーバだけを置いた構成とクライアントのイベント列で確認しました。
  サーバ撤回、再バインド、有効期限切れ、識別子変更、複数 WAN、転送、復旧は未認定です。
- 復元では、両 VM を `rd15-dhcp-vlan-3a18-pre` へ戻しました。
  一時 ISO と PVE 上の配置用ファイルを削除しました。
  VM219 と VM220 は、元の CD イメージで起動していることを確認しました。

# BFD の PVE 独立ピア試験

実施日: 2026-11-02（JST）  
対象ソースリビジョン: `79e947b5045d54661c92458c7cce39e196bb7a51`  
試験用 `routerd` SHA-256: `665a6b52e4fb01b90cd9359e5289dff35a3f07f2a24ae18d201f165bc0fc1174`

## 結果

VM219 と VM220 は VLAN 3132 上で FRR BFD を `Up` にし、BGP を
`Established` にしました。VM220 の FRR サービスを停止すると、VM219 は
BFD `Down` と BGP `Reconverging` を報告しました。VM220 の FRR サービスを
起動し直すと、VM219 と VM220 の BFD は `Up`、BGP は `Established` に戻りました。

## 実装した修正

systemd の `CapabilityBoundingSet` と `AmbientCapabilities` へ
`CAP_DAC_OVERRIDE` を追加しました。FRR の `/etc/frr/vtysh.conf` と
`frrvty` 制御ソケットは、通常の routerd の能力集合では参照できませんでした。
このため、実行中の `bfdd` が存在しても BFD コントローラーは利用不能として
報告していました。修正後の `routerd` は両 VM で FRR の BFD ピア状態を取得し、
設定を適用できました。

## 構成

- ルーター: VM219、`198.18.16.2`、AS 64520、`rd15-wan`
- 独立ピア: VM220、`198.18.16.1`、AS 64521、`rd15-bfd-up`
- 接続: `br-rd15-lab` の VLAN 3132
- BFD 間隔: 受信 300ms、送信 300ms、検出倍率 3
- VM219 の BFD: `BFD/pve-peer`、`BGPPeer/pve-peer`
- VM220 の BFD: `BFD/pve-router`、`BGPPeer/pve-router`

VM219 の WAN は非信頼ゾーンです。そのため、この試験用の新規 1.5 設定では、
WAN からルーター自身へ向かう UDP/3784 だけを許可する
`FirewallRule/allow-bfd-control` を明示しました。これは BFD の実通信に必要な
受信許可であり、全 UDP を許可する変更ではありません。

## 観測

- 修正前は、両 VM の BFD コントローラーが `vtysh.conf` の権限拒否を報告した
- 修正後は、両 VM の `vtysh -c 'show bfd peers json'` が相手の識別子と
  `status: up` を返した
- VM219 の BFD 資源は `phase: Up`、`peerStates: {"198.18.16.1":"Up"}`
- VM220 の BFD 資源は `phase: Up`、`peerStates: {"198.18.16.2":"Up"}`
- 両側の BGP 資源は `phase: Established`、`establishedPeers: 1`
- VM220 の FRR 停止後、VM219 は BFD `Down` と BGP `Reconverging`、
  `establishedPeers: 0` を報告した
- FRR の再起動後、両側の BFD は `Up`、BGP は `Established` に復帰した

障害検出時間を製品目標として定めてはいません。試験では、設定済みの BFD
検出条件の後に状態変化を観測できるまで待機しました。

## 復帰

両 VM は試験前の正本設定へ戻しました。VM219 は 21 資源、generation 41 の
`Healthy` 状態です。VM220 は 13 資源、generation 55 の `Healthy` 状態です。
両 VM で試験用 `routerd` バイナリーと systemd 定義を元へ戻し、FRR は停止・
無効状態へ復元しました。試験用 CD-ROM、PVE ホストの一時 HTTP 配信、
`198.18.52.254/24` の一時アドレスも取り外しました。

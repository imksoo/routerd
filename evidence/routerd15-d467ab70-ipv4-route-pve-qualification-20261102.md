# IPv4 経路の PVE 分離 VLAN 実通信記録

対象実行リビジョンは `d467ab70ffff3e1b7763f084a945ea1ba9939db3` です。現行の `1f0b694a` との差分は資格記録だけで、実行コードに差分がないことを確認しました。Linux の PVE 分離 VLAN で、静的 IPv4 経路の実通信、構成撤回、再適用、`routerd` 再起動後の復旧を確認しました。

## 構成

- VM219: `routerd`。VLAN 3131 の LAN は `198.18.91.1/24`、VLAN 3132 の WAN は `198.18.92.1/24`。
- VM220: VLAN 3132 の独立上流。`198.18.92.2/24` と到達先 `203.0.113.9/32` を持つ。
- VM224: VLAN 3131 の独立クライアント。`198.18.91.10/24` を使用。
- VM219 の `IPv4Route/peer-network`: `203.0.113.0/24 via 198.18.92.2 dev rd15-wan`。

## 観測結果

1. VM219 のカーネル経路検索は、`203.0.113.9` の次ホップとして `198.18.92.2` を返しました。
2. VM224 から `203.0.113.9` への ICMP は 3/3 応答しました。TTL は 63 で、VM219 による中継を示しました。
3. `IPv4Route` だけを除く同一構成へ `routerctl apply --replace` で置換すると、VM219 の対象経路は消えました。VM224 の新規 ICMP は VM219 から `Destination Net Unreachable` を受け、VM220 へ転送されませんでした。
4. 経路を再適用すると、カーネル経路検索は再び `198.18.92.2` を返し、VM224 の ICMP は 3/3 応答へ復帰しました。
5. `systemctl restart routerd` 後も、同じカーネル経路と VM224 の ICMP 3/3 応答を確認しました。

## 復帰

VM219 は元の実行物、構成、状態領域、`routerd` と `routerd-dnsmasq` の稼働状態へ復元しました。VM220 は試験用 VLAN、到達先アドレス、復路を撤去して元の `routerd` を再稼働しました。VM224 は試験用 VLAN を撤去して停止しました。候補 ISO は元の ISO に差し戻して削除しました。

## 範囲外

- `ClusterNetworkRoute`、動的クラスタ更新、複数経路、方針経路、BGP からカーネル経路への反映、障害時の経路選択は未確認です。
- IPv6 経路、FreeBSD、物理回線は未確認です。
- この記録は上記リビジョンと PVE 構成に限定され、経路制御全体または製品全体の合格を示しません。

# IPv6 ホスト送信方針の PVE 実通信・撤回・復旧

対象リビジョンは `81444257bd89a9f3f25ed9fd7e7f1023c6fa18c9` です。候補配布物の
SHA-256 は `a07047cfc3bc3fc9131fc2bbda7e052bc736f0e52cc1deb7229fafa5cdb039a7`、
VM219 に導入された `routerd` 実行物の SHA-256 は
`95b231277f36fcea554f53ebec74c097b3ec312fcfc41a9170c392eed97043b8` でした。

## 構成

- PVE の VM219 を候補、VM220 を独立ピアとして使用しました。両者は VLAN 3132 の
  `rd15-wan` を使用します。VM224 は試験前の停止状態から変更していません。
- VM219 は `2001:db8:3132::1/64`、VM220 は `2001:db8:3132::2/64` を持ちます。
  VM220 のループバック `2001:db8:3150::99:18081` で独立した HTTP 応答を待ち受けました。
- 新規 1.5 構成は `EgressRoutePolicy` の IPv6 `hostTraffic: true` を一つだけ定義しました。
  静的ゲートウェイは `2001:db8:3132::2`、経路表は 120、優先度は 10120 です。
  WAN の非信頼ゾーンと既定の防火壁方針を同時に定義しました。

## 観測結果

1. 配布物のハッシュと構成の検証に成功しました。`routerctl apply --replace` は世代 1、
   `Healthy`、四資源となりました。候補は優先度 10119 の `main` 経路表を抑制する規則、優先度
   10120 の経路表 120 規則、および送信元 `2001:db8:3132::1` を持つ既定経路を導入しました。
2. VM219 から `http://[2001:db8:3150::99]:18081/` へ送った新規 HTTP は応答しました。
   VM220 の HTTP 記録は送信元 `2001:db8:3132::1` を示しました。これは候補機自身が
   IPv6 方針の既定経路を通って独立ピアへ到達した観測です。
3. 空の新規 1.5 構成へ置換すると、所有する二つの規則と経路表 120 の既定経路は消えました。
   その後の新規 HTTP は接続できませんでした。
4. 同一の方針構成を再適用すると、二つの規則と既定経路が再導入されました。新規 HTTP は
   再び応答し、VM220 は同じ候補送信元を記録しました。

## 復元

VM219 と VM220 は試験前のスナップショットへ戻しました。試験用 ISO、PVE の一時配置、
スナップショットを削除しました。VM219 と VM220 は稼働、VM224 は停止という試験前の状態を
確認しました。

## 範囲外

- この `hostTraffic` 機能は候補機自身が生成する IPv6 通信を対象にします。LAN 転送や
  IPv4 方針を変更する機能ではありません。
- ハッシュ方式、マーク方式、動的ゲートウェイまたは送信元、VRRP、物理 WAN 障害、
  この構成でのサービス再起動、FreeBSD、および routerd 1.0 全機能の合格判定は対象外です。

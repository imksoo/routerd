# DS-Lite の委譲 IPv6 送信元、失効、再取得の PVE 実通信記録

## 結論

Linux 候補 `4655971e` は、DHCPv6-PD で得たプレフィックスから DS-Lite の外側送信元を生成し、分離 VLAN の独立クライアントから独立 AFTR への IPv4 HTTP を転送しました。独立 Kea を停止してリースを自然失効させると、委任送信元、DS-Lite、既定経路、通信が撤回されました。Kea を戻すだけで、候補プロセスを再起動せずに同じ経路と通信が自動復旧しました。

## 実行対象

| 項目 | 値 |
| --- | --- |
| 実行リビジョン | `4655971e87ca1dcae740dd8d59190a971aab120b` |
| Linux 配布物 SHA-256 | `19f26c7cc938bb98d83ad0e92d0ec7fc289d064403b128c56b2228198484b7c9` |
| 構成 SHA-256 | `6556899ed834022ab316ac92f25bc7bf8fab91c7618a6029d3ee57e5f217447e` |
| 候補ルーター | PVE VM219 |
| 独立 Kea、AFTR、HTTP端点 | PVE VM220、VLAN 3132 |
| 独立 IPv4 クライアント | PVE VM224、VLAN 3131 |
| DHCPv6-PD | `2001:db8:1500::/60`、更新10秒、再バインド20秒、有効期限35秒 |
| DS-Lite 外側 | 候補 `2001:db8:1500::100`、AFTR `2001:db8:16::1` |
| DS-Lite 内側 | 候補 `192.0.0.2`、AFTR `192.0.0.1` |

構成は新規の1.5形式です。旧設定、旧状態データベース、形式変換は使用していません。

## 観測結果

1. 新規状態領域で12資源を適用し、すべて `Healthy` となりました。候補は `2001:db8:1500::1/64` と、DS-Lite専用の `2001:db8:1500::100/128` を LAN 側へ設定しました。
2. `rd15-dslite` はローカル `2001:db8:1500::100`、AFTR `2001:db8:16::1`、MTU 1454、内側 IPv4 `192.0.0.2` として生成されました。IPv4既定経路は `default via 192.0.0.1 dev rd15-dslite metric 10` でした。
3. VM224 の HTTP は本文 `routerd15 delegated source dslite traffic` を受信しました。VM220 の HTTP記録は送信元 `192.0.0.2`、候補の接続追跡は元の `198.18.15.10` と変換後の `192.0.0.2` を同一の完了済みフローとして記録しました。
4. VM220 の AFTR捕捉では、`192.0.0.2` から `192.0.2.1:18080` 宛ての TCP SYN に MSS 1414 が設定されていました。候補の NAT44 と TCP MSS 制御にも同じ値がありました。
5. Keaだけを停止して有効期限を満了させると、候補は `DHCPv6PrefixDelegation/wan-pd` を `Expired`、`IPv6DelegatedAddress/lan-v6` を `PDLeaseStale`、`DSLiteTunnel/isolated-aftr` を `LocalIPv6Missing` と報告しました。`rd15-dslite`、`2001:db8:1500::100/128`、DS-Lite既定経路は消え、VM224 の新規 HTTP はタイムアウトしました。
6. Keaだけを再開すると、候補は約3秒でプレフィックスを再取得し、委任送信元、DS-Lite、既定経路を再生成しました。候補の状態は再び12資源 `Healthy` となり、VM224 の新規HTTPとVM220の `200` 記録が復帰しました。

## 復元

VM219、VM220、VM224 を試験前スナップショットへ戻しました。試験用ISO、CD-ROM接続、一時アーカイブ、一時構成、スナップショットを削除しました。VM219とVM220は基準状態で起動し、VM224は停止しています。

# VRRP と DHCP の PVE 分離 VLAN 現行実行記録

対象実行リビジョンは `d467ab70ffff3e1b7763f084a945ea1ba9939db3` です。現行 `d121dcb9` との差分は資格記録だけで、実行コードに差分がないことを確認しました。PVE の未使用 VLAN 3152 で、二つの routerd と独立クライアントによる VRRP、VIP、DHCP の選出・障害切替・復旧を確認しました。

## 構成

- VM221: 優先度 150、アドレス `172.18.0.2/16`、VRID 51。
- VM222: 優先度 100、アドレス `172.18.0.3/16`、VRID 51。
- 仮想アドレス: `172.18.0.1/32`、`preempt: false`。
- VM223: 独立 DHCP クライアント。VLAN 3152 のみを試験対象とする。
- DHCP プール: `172.18.1.100` から `172.18.1.199`。既定経路は仮想アドレス。

両ルーターは、元の実行物・構成・状態を退避した後、空の状態領域から候補自身が管理する `routerd-dnsmasq.service` を生成して試験しました。

## 観測結果

1. VM221 は master、VM222 は backup となり、VM223 は VM221 の `172.18.0.2` から `172.18.1.142/16` と既定経路 `172.18.0.1` を DHCP で取得しました。VIP への ICMP は 3/3 応答しました。
2. VM221 を強制停止すると VM222 は master へ遷移し、仮想アドレスを引き継ぎました。VM223 の 200 ミリ秒間隔の ICMP 観測では停止中に欠落区間があり、その後の応答を確認しました。この時間は今回の観測値であり、切替時間の目標値ではありません。
3. VM223 は VM222 の `172.18.0.3` から `172.18.1.143/16` と仮想アドレスの既定経路を DHCP で再取得しました。VM222 の DHCP サービスは UDP 67 番を VLAN 3152 に待ち受け、リースを記録しました。VIP への ICMP は 3/3 応答しました。
4. VM221 を再起動後、VM221 は backup、VM222 は master のままでした。これは `preempt: false` に一致します。VIP への ICMP は 3/3 応答しました。

## 復帰

VM221 と VM222 は元の `58b66728` の実行物、構成、状態、追加 CD-ROM へ戻しました。候補 ISO とクライアントの試験用 DHCP コールバックを削除しました。最終状態は VM221 が master、VM222 が backup、VM223 は `172.18.1.143/16` と仮想アドレスの既定経路を保持し、VIP の ICMP は 3/3 応答です。

## 範囲外

- RouterdCluster の選出、フェンシング、分断時の二重 master 防止、永続状態の同期、接続追跡同期、WAN/NAT/DNS を含むデータプレーン継続は未確認です。
- 既存 TCP 接続、IPv6、物理障害、FreeBSD は未確認です。
- この記録は VRRP・VIP・DHCP の限定した PVE 試験であり、冗長化全体または製品全体の合格を示しません。

# routerd 1.5 現行 Linux PVE WireGuard 親子資源の撤回・復旧検証

実行リビジョンは `edffd8a0` です。
WireGuard の実通信、親復旧、構成撤回、再適用後の復旧を PVE で確認しました。

- 実行物: `routerd v20261027.1620 (edffd8a0)`
- 配布アーカイブ SHA-256: `e44cf91f10ff3ff46755cd57aa8656d711985eca5b3ce5ed3b6433147e8aafdc`
- 候補機: 隔離 PVE VM219
- 独立ピア: 隔離 PVE VM220
- 外側ネットワーク: VLAN 3132、候補機 `198.18.16.2:51820`、独立ピア `198.18.16.1:51821`
- 内側ネットワーク: 候補機 `192.0.2.1/32`、独立ピア `192.0.2.2/32`

## 構成と境界

- `WireGuardInterface/parent` が `wg-rd15` を所有し、`IPv4StaticAddress/wg-v4` と `IPv4Route/wg-route` が親を参照しました。
- `FirewallZone/wan` は未信頼の外側インターフェースと WireGuard UDP の受信許可を持ち、`FirewallZone/vpn` は認証済みトンネル内側を `trust` として扱いました。
- 独立ピアにはトンネル内の ICMP エコー要求 だけを受ける一時規則を追加しました。

## 観測結果

- `routerd validate` は通常構成と撤回構成の両方で成功しました。
- 認証済みハンドシェイクと、両方向の送受信量増加を観測しました。
- 候補機から独立ピアへの ICMP は 3/3 応答しました。
- `ip link set wg-rd15 down` の後、routerd が親を再適用しました。親、子アドレス、経路は戻り、ICMP は 3/3 応答しました。
- 撤回構成への置換で親、子アドレス、経路は消え、独立ピアからの ICMP は 0/2 応答でした。
- 通常構成の再適用後、親、子アドレス、経路が戻り、独立ピアからの ICMP は 3/3 応答しました。

## 復元確認

- VM219、VM220、VM224 は試験前のスナップショットへ戻しました。試験用 ISO 接続、スナップショット、PVE 上の試験 ISO と一時ディレクトリを削除しました。
- 鍵ローテーション、複数ピアの経路制御、高可用性、FreeBSD、物理回線は未検証です。

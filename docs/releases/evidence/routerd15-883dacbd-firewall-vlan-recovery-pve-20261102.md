# Linux 防火壁 VLAN 撤回・復旧の実通信試験

## 結果

`883dacbd` の Linux 候補パッケージで、独立 VLAN 上の防火壁方針、NAT44、構成撤回、再適用後の復旧を確認しました。

## 実行対象

- ソースリビジョン: `883dacbd3df3f0725e07f2985ccfcf559089b3f4`
- パッケージ SHA-256: `cd763b1a1356053dd6e7400358119a0edfbf23c674a16a4fd07ff580d7de83ad`
- 仮想マシン: VM219 が候補ルーター、VM220 が WAN・管理側の独立ピア、VM224 が LAN 側の独立クライアントと HTTP 応答器
- 分離経路: VLAN 3131 が LAN、VLAN 3132 が WAN、VLAN 3133 が管理
- 構成: 外部管理の `rd15-lan`、`rd15-wan`、`rd15-admin`、LAN から WAN への NAT44、信頼・非信頼・管理ゾーン

## 観測

1. VM224 から VM220 の WAN HTTP 応答器へ到達し、応答は NAT44 後の送信元 `198.18.16.2` を記録しました。
2. VM224 から管理側 HTTP 応答器への接続は時間切れでした。候補の `lan_to_admin` カウンターは 3 パケットを拒否しました。
3. VM220 の送信元を VLAN 3132 に固定して LAN HTTP 応答器へ接続すると時間切れでした。候補の `wan_to_lan` カウンターは 3 パケットを拒否しました。
4. 空の新規 1.5 構成を全置換で適用すると `Healthy` となり、LAN→WAN HTTP は時間切れでした。未宣言の許可経路は残りませんでした。
5. 読み取り専用 ISO 上の元構成を別名へ複製して再適用すると、全9資源が `Healthy` となりました。LAN→WAN は再び `198.18.16.2`、LAN→管理と WAN→LAN は再び時間切れでした。

## 範囲外

IPv6 防火壁、詳細な規則選択子、ポート転送、既存接続の維持、速度制限、物理回線、FreeBSD は未確認です。
この結果は防火壁機能全体、Linux 全体、または置換可能品質の合格を意味しません。

## 復元

VM219、VM220、VM224 を試験前のスナップショットへ戻しました。
VM219 と VM220 の既存 `routerd` サービスは `active`、VM224 は停止状態です。
試験用 ISO、一時配置、三つの試験用スナップショットは削除済みです。

# Linux 管理経路のデータ転送障害・復旧試験

## 結果

候補 `routerd` によるLANからWANへの実通信を断っている間も、独立VLANの管理経路は維持されました。WAN側のVLANと終端の復路を復帰すると、データ通信と管理通信の両方が戻りました。

## 実施条件

- 実行リビジョン: `883dacbd3df3f0725e07f2985ccfcf559089b3f4`
- パッケージ SHA-256: `cd763b1a1356053dd6e7400358119a0edfbf23c674a16a4fd07ff580d7de83ad`
- VM219 は VLAN 3131、3132、3133 の `rd15-lan`、`rd15-wan`、`rd15-admin` で候補実行物を起動しました。
- VM224 は VLAN 3131 の `198.18.15.10/24`、VM220 は VLAN 3132 のHTTP終端 `203.0.113.10:18090` と VLAN 3133 の管理送信元 `198.18.17.10/24` です。
- 候補構成は外部所有の三インターフェース、`203.0.113.0/24 via 198.18.16.1`、IPv4転送、信頼LAN・WAN、防御済み管理経路を宣言します。

## 観測

- 基準時はVM224からWAN終端へのHTTPが200、VM220からVM219の管理HTTPも200でした。
- VM220のVLAN 3132 子インターフェース `rd15-peer` を停止すると、VM224からのデータHTTPは接続不能となりました。
- 同じ障害中に、別のVLAN 3133 からの管理HTTPは200でした。
- `rd15-peer` の復帰後、終端側の `198.18.15.0/24 via 198.18.16.2` 復路を再設定しました。データHTTPと管理HTTPはともに200へ復帰しました。
- 最終時点で管理送信元許可規則のカウンターは6パケットでした。

## 手順上の訂正と未確認範囲

初回の復旧確認では、VM220の基準 `routerd.service` が防火壁表を再生成し、独立したWAN終端へのTCP接続を遮断しました。この終端の基準サービスを試験中だけ停止・実行時マスクし、生成済み防火壁表を削除してから試験をやり直しました。これは候補の機能障害ではなく、独立終端の準備不備です。

候補の通常 `systemd` サービス経路、管理経路自体の障害、既存接続、IPv6、SSH、複数管理インターフェース、FreeBSD、および製品全体の合格は対象外です。環境復旧はこの記録の後に別途確認します。

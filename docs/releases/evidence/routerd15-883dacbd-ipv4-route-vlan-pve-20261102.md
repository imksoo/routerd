# Linux IPv4 静的経路の分離 VLAN 実通信試験

## 結果

`883dacbd3df3f0725e07f2985ccfcf559089b3f4` の Linux パッケージで、独立クライアントの IPv4 通信、経路撤回、同一新規設定の再適用による復旧を確認しました。

## 構成と観測

- パッケージ SHA-256: `cd763b1a1356053dd6e7400358119a0edfbf23c674a16a4fd07ff580d7de83ad`
- VM219 は候補。`IPv4Route/peer-target` が `203.0.113.0/24 via 198.18.16.1 dev rd15-wan metric 79` を所有。
- VM220 は VLAN 3132 の独立上流で、`203.0.113.10:18090` の HTTP 応答先。
- VM224 は VLAN 3131 の独立クライアント。`198.18.15.10` から候補を既定ゲートウェイとして使用。
- VM224 の HTTP 要求は VM219 を経由して VM220 へ到達しました。
- 空構成を `routerctl apply --replace` で適用すると、候補のカーネル経路は消え、VM224 の新規 HTTP 接続はタイムアウトしました。
- 読み取り専用 ISO から退避した同一 1.5 設定を再適用すると、経路は同じ次ホップとメトリックで復元し、VM224 の HTTP 通信も復旧しました。

## 復元と未確認範囲

三台を試験前状態へ戻し、スナップショット、ISO、候補プロセス、VLAN 子インターフェース、一時資産を削除しました。VM219・VM220 は稼働、VM224 は停止し、両基準 `routerd` は active です。

ClusterNetworkRoute、動的クラスタ更新、複数経路、方針経路、BGP 学習経路、再起動、IPv6、FreeBSD、および製品全体の合格は対象外です。

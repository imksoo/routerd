# Linux 設定ライフサイクルの分離 VLAN 実通信試験

## 結果

現行 Linux パッケージで、不正設定の拒否、正規設定の保持、候補プロセス再起動後の経路と実通信の復旧を確認しました。

## 観測

- パッケージ SHA-256: `cd763b1a1356053dd6e7400358119a0edfbf23c674a16a4fd07ff580d7de83ad`
- 正規設定は VM224 から VM219 を経由し、VM220 の `203.0.113.10:18090` へ到達しました。
- 不正な `IPv4Route` の `destination: not-a-prefix` は、`spec.destination must be an IPv4 CIDR` として制御 API に拒否されました。
- 拒否前後で正規設定ファイルの SHA-256 は `a391d8d6d969ed466d53cfa3e1c46fdb95d7389530e700f1b833736a5b4a87e3` のままでした。
- 拒否後も `203.0.113.0/24 via 198.18.16.1 dev rd15-wan metric 79` は残り、VM224 の HTTP 通信も継続しました。
- 候補 `routerd` を停止して同じ正規設定・状態領域で再起動した後も、同じカーネル経路と VM224 の HTTP 通信が復旧しました。

## 復元と未確認範囲

VM219、VM220、VM224 は試験前状態へ戻し、試験用 ISO、スナップショット、候補プロセス、VLAN 子インターフェース、一時資産を削除しました。最終状態は VM219・VM220 稼働、VM224 停止で、基準 `routerd` は active です。

設定中断時の電源断、全 API・CLI の削除とロールバック、保存領域破損、複数同時変更、FreeBSD、および製品全体の合格は対象外です。

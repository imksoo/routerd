# routerd 1.1 の現行要件

2026-11-14更新。作業規約の正本は[AGENTS.md](../../AGENTS.md)。この文書は現在の製品要件だけを定める。完了した作業計画、監査時点の判定、試行記録は残件一覧として残さない。実施する作業は利用者の現在の指示で決める。

## 対象と棚上げ

現在の対象は homert02/03、k8s-rt01/02、pve-rt01〜08 と実際の相手機器である。

**Cloud SAMは別開発まで棚上げする。** 今回の完了条件・残件・質問待ちへ戻さず、新規クラウド資源や課金テストを追加しない。既存コードと共有依存は維持する。k8s-rt/pve-rtで使用するローカルSAM・IPIP・BGPは棚上げの対象ではない。Cloud SAMを別途再開する場合の参照先は `nwadmin03.lain.local:~/routerd-labs` とする。

## 設定の正本と反映

routerdが反映する設定はコンフィグを正本とする。CLI/APIの永続的な変更も同じ設定へ反映し、生成ファイルや手動変更を設定へ逆輸入しない。

- 同じ設定のapplyで不足・相違を修復し、設定と有効な動的状態に不要な実体を撤去する。手動追加を保持する所有台帳や作成履歴は使わない。
- 設定hashや以前のAppliedだけで一致とせず、必要な実体を観測する。観測・OS操作・保存の失敗を隠さない。
- OS基盤、DHCP/PDの有効リース・識別情報・期限、BGP選択経路、SAM/VRRPの役割・排他など、現在の設定が必要とする動的状態は維持する。通信中のARP/ND、conntrack、DNS cacheを毎applyで全消去しない。
- WireGuard peerとVXLAN転送先は現在の設定に従う集合とし、設定前の集合は保存しない。
- planは観測と判断を行い、本番の設定・状態を変更しない。実通信と未完了理由をstatusへ正しく示す。

既存ホストの取り込みは、人が選んだ物理NICと静的IPv4/IPv6アドレスの候補を `routerctl import` で得て、ホスト全体の必要な設定へ統合する。動的な取得値や経路を静的設定へ自動変換しない。完全設定を置換する操作はplan/applyの両方で `--replace` を明示し、部分upsertと区別する。

## 実装と確認

具体型と直接的な制御を使う。外部入力は実際の境界で復号・検証し、内部のJSON/YAML往復、可変状態の二重正本、不要な能力推測や互換経路を増やさない。必要な状態・イベントの保存順序、原子性、処理済み位置、容量と保持期限、HAの排他は保つ。

開発・編集・ビルドは使い捨てKubernetes Podで行う。変更は小さく公開し、homertは `~/homert02`、k8s-rt/pve-rtは `~/k8s` の既存Codexと分担して実機確認する。モック、偽応答、模擬ネットワーク、新規の検証基盤は作らない。テストコードの追加・増補は対象を特定した事前の明示許可がある場合だけとする。

確認は現在の変更に必要な実入力・状態・順序を選び、完了した全ケースを理由なく繰り返さない。再起動の合否を任意の秒数で決めず、コンソール、QGA、DHCP・登録・経路の実際の進行と実エラーを見る。既存のプロトコル期限と観測上の待ちを混同しない。

## 配布・復帰・後片付け

既存のUTC日時版 `vYYYYMMDD.HHmm`、公式配布物、インストーラー、Live ISOを使う。配布物をSHA照合し、冗長構成を同時停止せず、対象ごとに実起動・実通信・復旧経路を確認する。

ディスク稼働のhomertでは現在の設定・鍵・最新DB・有効リースを維持する。Live ISOでは既存の[状態DBの運用方針](../operations/state-database.md)に従い、永続設定と鍵から再構築する。再構築できない状態がないか確認し、古いDBを新規DBへ無条件に上書きしない。実装済みの `noprompt` で不要なメディア取り外し入力待ちを省くが、再起動時間を保証するものではない。

必要な成果物と短い変更説明を公開後、作業Pod/namespace、キャッシュ、一時転送物、不要なエビデンスを削除確認する。ソース、現設定・鍵・DB、必要な旧版1世代と他作業のデータを消さない。製品の変更履歴は[変更履歴](../releases/changelog.md)に集約し、古い計画や監査結果から完了済み作業を再生成しない。
